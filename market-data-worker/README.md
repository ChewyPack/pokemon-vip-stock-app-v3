# PokePrizePool Market Data Worker (Staging)\n\nThis worker imports Pokémon catalog and price snapshots from TCGCSV into the staging R2 bucket. It does not write to D1 and does not touch production.\n\n## What it does\n\n- Checks the TCGCSV last-updated marker at most once per UTC day while no import is in progress.\n- Imports Pokémon category 3 in batches of eight groups per invocation to stay within Worker execution limits.\n- Stores each group as `snapshots/YYYY-MM-DD/groups/GROUP_ID.json`.\n- Writes an in-progress/finished manifest and persists a cursor so scheduled runs resume.\n- Uses a descriptive User-Agent and stores product metadata plus subtype-specific prices. Missing prices remain null or empty, never zero.\n- Provides `GET /health` and token-protected `POST /admin/run` for manual testing.\n\n## Deploy from GitHub\n\n1. In Cloudflare, open Workers & Pages and create a Worker connected to this GitHub repository.\n2. Set the root directory to `market-data-worker` and entry point to `src/index.js`, or deploy with Wrangler using this directory.\n3. Use Worker name `pokeprizepool-market-data-staging`.\n4. Add R2 binding `MARKET_DATA` to `pokemon-vip-market-data-staging`. Do not bind the production bucket.\n5. Add secret `ADMIN_TOKEN` with a long random value. Keep it private.\n6. Confirm Cron Trigger `*/15 * * * *` (every 15 minutes UTC). The source marker is checked only once daily; active imports resume from saved progress.\n7. Deploy and visit `/health`; expect JSON with `ok: true`.\n8. To run one batch manually, send a POST request to `/admin/run` with header `Authorization: Bearer YOUR_ADMIN_TOKEN`. Never put the token in a URL or public code.\n\n## Data format\n\nEach group snapshot contains source, source update time, snapshot date, group metadata, product name/ID, set/group, image URL, extended data and all price variants. Price fields are numbers or null.\n\n## Limitations and safety\n\n- TCGCSV prices are TCGplayer market-price data, not sold listings, guaranteed live offers, or condition-specific pricing.\n- This first worker stores snapshots only. It does not yet wire collection/wishlist UI or Market Intelligence to these snapshots; those are follow-up staging changes after import is verified.\n- At most eight groups are processed per run; a failed group is recorded and yields `complete_with_errors`. Do not treat that as a complete dataset.\n- All data is staging only. Never change `main`, production D1, production domain, or production bucket.\n
